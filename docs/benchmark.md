# Tests

Two tests so far. Neither showed a gain in answer accuracy for ordinary questions: a capable agent with grep already
finds facts in plain docs, even among 300 of them. What docs-1 did show is reliable stale-doc detection and faster,
complete answers to "which docs cover this file". Both are reported as they came out.

## Test 1: a real project with 38 docs

- **Project:** a real application repository with 38 Markdown docs (`docs/`, `specs/`, `design/`, `packaging/`).
- **Setup:** a Claude Haiku agent applied this skill to a copy of the repository ("set up docs-1", frontmatter in place,
  no files moved): 36 docs got frontmatter and a 52-line `docs/INDEX.md` was generated. 86 turns, $0.03.
- **Questions:** 14, written by Claude Sonnet from the docs (5 needle facts, 4 how-to, 3 why, 2 needing two docs).
- **Answering:** Claude Haiku with Read, Grep and Glob, 2 answers per question. The original copy was told the docs are
  in `docs/` and other Markdown files; the docs-1 copy was told to start at `docs/INDEX.md`.
- **Grading:** Claude Sonnet, blind, 2 passes, score 0 to 2.

| | score | turns per answer | $ per answer | opened the index |
|---|---|---|---|---|
| original docs | 2.00 | 6.8 | 0.0033 | n/a |
| with docs-1 | 1.98 | 6.3 | 0.0038 | 28 of 28 |

At 38 docs, grep already finds everything, so both score at the ceiling and the index saves about half a turn. What
this test does not cover, and where the design is aimed: hundreds of docs, stale docs (detected through `covers` and
`verified`, checked by hand here but not benchmarked), finding the docs for a file before editing it, and keeping the
index current over time. The setup run did surface one real gap, fixed since: the script only indexed `docs/`, and now
indexes any Markdown file in the repository that has docs-1 frontmatter.

## Test 2: 309 synthetic docs, with replaced and outdated docs

- **Project:** a made-up product, so the answering model cannot know it from training. 309 docs over 12 areas, 144 of
  them near-duplicate per-region variants, 25 old docs that a newer doc replaces, and 15 docs whose stated value no
  longer matches the code (the code changed in a later commit). Real git history.
- **Conditions:** plain docs (no frontmatter, no index, old docs unmarked); plain docs plus the sentence "Code at HEAD
  wins over a doc; a doc may be outdated" in the prompt; docs-1 (frontmatter, index split per area, old docs in
  `archive/`, the same sentence, and the script).
- **Questions:** 44 (needle facts, "what is the current X" where an old and a new doc disagree, facts where the doc is
  outdated, and "which docs must I update if I change this file"), then 36 of them again with the subject reworded so
  grep on the question's words fails. Claude Haiku answered, 2 answers per question and condition.

| | plain | plain + trust sentence | docs-1 |
|---|---|---|---|
| accuracy, original wording (0 to 1) | 0.974 | 0.989 | 1.000 |
| accuracy, reworded | 0.972 | 0.965 | 0.993 |
| answers that repeated an outdated doc value | 4 of 40 | 1 of 40 | 1 of 40 |
| "which docs cover this file": recall | 0.95 | 0.94 | 1.00 |
| "which docs cover this file": turns | 7.9 | 8.9 | 5.7 |
| turns on other questions (original wording) | about 5.3 | about 5.2 | about 6.6 |

What it shows:

- **Accuracy is a tie.** No accuracy difference is larger than about 2 standard errors. The test was still too easy
  to separate the conditions.
- **The trust sentence does most of the work against outdated docs.** One sentence in `AGENTS.md` cut answers that
  repeated an outdated value from 4 to 1; docs-1 added nothing measurable on top.
- **Stale detection works without a model.** `docs_index.py check` flagged all 15 outdated docs, plus 6 docs whose
  covered code changed only cosmetically, and none of the other 263. So every truly outdated doc was found, and 15 of
  21 flags were real.
- **Docs for a file are faster and complete** with `covers`: every doc found, in about 3 fewer turns.
- **The cost:** about one extra turn (reading the index) and 10 to 20% more per answer on ordinary questions.

Limits: synthetic docs; the frontmatter was generated by script from the ground truth, not maintained by an agent over
time, which is the best case for docs-1; one answering model; most docs named their source file, which helps the plain
layout too. Two gaps found by this test are fixed: `check` missed same-day changes when a doc had no commit recorded,
and there was no command to mark a doc as re-checked (`verify`).
